# aerial-scene-nav

Семантическое описание наблюдаемой сцены по аэроснимку и (следующие этапы) локализация по эталонной базе местности.
Это переписанный с нуля проект на основе прототипа `semantic_scene_description` (практика 2026).

## Что исправлено относительно прототипа

| Было | Стало |
|---|---|
| `texture` не доходил до датасета/модели, каналы задавались глобальными `USE_TEXTURE`/`IN_CHANNELS` | Каналы выводятся из `data.features` в конфиге эксперимента; `train.py` проверяет форму реального батча (`assert`) |
| `A.Normalize()` рассчитан на 3 канала | Собственные аугментации на numpy: яркость/шум только для RGB, геометрия — для всех каналов |
| Текстурные карты нормировались min-max по каждому снимку | Фиксированный масштаб, одинаковый для всех снимков; признаки считаются по целому тайлу до нарезки |
| Три разных списка названий классов | Один источник: `scenenav/classes.py` |
| Нет сдвига меток и `ignore_index` | Цветные маски переводятся в индексы, `Unlabeled` -> 255 и исключается из потерь и метрик |
| mIoU: отсутствующие классы считались как 0 | Отсутствующий класс -> NaN, среднее по присутствующим |
| `scheduler.step(mean_iou)` у CosineAnnealingLR | `scheduler.step()` без аргумента |
| Модель по умолчанию 64 каналов, при этом названа Light | Явный `base_channels` в конфиге либо предобученный энкодер (`smp_unet`) |
| Морфологии в коде не было | `scene/postprocess.py` |
| `random.choice` в тексте описания | Детерминированное описание, `scene/vector.py` |
| Разбиение случайное/по окнам | Разбиение **по тайлам**, `check_split` предупреждает о пересечениях и редких классах |
| Один запуск, один seed | Конфиг на эксперимент, несколько seed, сводка `scenenav.compare` |

## Быстрый старт

```bash
pip install -r requirements.txt

# 1) Подготовка датасета (Kaggle: humansintheloop/semantic-segmentation-of-aerial-imagery)
python -m scenenav.data.prepare_dubai --raw "<папка с Tile 1..N>" --out data/processed/dubai
#    Скрипт печатает доли классов по тайлам. По ней выберите train/val/test тайлы в configs/base.yaml.

# 2) Один эксперимент
python -m scenenav.train --config configs/dubai_rgb.yaml --seed 42

# 3) Серия: 5 вариантов признаков x 3 seed (на 72 снимках разброс между seed большой, один запуск ничего не доказывает)
for cfg in rgb rgb_lbp rgb_entropy rgb_variance rgb_gabor; do
  for s in 1 2 3; do python -m scenenav.train --config configs/dubai_$cfg.yaml --seed $s; done
done
python -m scenenav.compare runs test

# 4) Тесты
python -m unittest discover -s tests -v
```

## Структура

```
configs/            base.yaml + по одному файлу на эксперимент (features: [rgb] | [rgb, lbp] | ...)
scenenav/classes.py       схема классов, RGB-маска -> индексы
scenenav/features/        текстурные признаки (LBP, энтропия, дисперсия, Габор)
scenenav/data/            prepare_dubai.py (подготовка), dataset.py (окна, аугментации)
scenenav/models/          свой U-Net и фабрика (smp_unet)
scenenav/losses.py, metrics.py, infer.py, train.py, compare.py
scenenav/scene/           postprocess.py (морфология), vector.py (вектор S, описание сцены)
tests/
```

## Состояние проверки

Проверено прогоном: классы и маски, текстуры, метрики, подготовка данных, конфиги, морфология, вектор сцены,

`train.py`, `models/`, `losses.py`, `infer.py`. Запустите `tests/test_torch_parts.py` у себя первым делом.

## Ограничения датасета Dubai

* Спутниковые снимки (MBRSC), а не дроновые; всего 72 изображения в 6–8 тайлах (в источниках числа расходятся).
* Разрешение (м/пиксель) в описании датасета не указано, поэтому ошибки локализации сначала считаются в пикселях/ячейках.
* Классов 5 (+ Unlabeled): здания, открытая местность, дороги, растительность, вода. Класса «лес» нет.
